Decision brief

Overview

Recommend 01: searchable reference table. It keeps bindings, modes, commands, and source lines together for complete, mode-aware lookup.

01 / Reference table

See every mapping at once. Combine text, mode, and task filters.

Best for precise lookup and comparing mode-specific behavior. Denser before filtering.

02 / Task groups

Start with a task, then open a native disclosure to reveal its mappings.

Best for learning by intent. Comparing tasks requires opening more than one group.

03 / Command finder

Type an intent, move through results, and inspect one mapping inline.

Best for focused keyboard lookup. Only the selected result exposes full command details.

Assumptions, source scope, and prototype limitations
  • Same source throughout: all three options use the same 26 mapping declarations from lua/config/keymaps.lua:5–45.
  • Scope is custom mappings: this is not the full LazyVim defaults catalog or a live inventory of effective runtime mappings.
  • Modes remain distinct: repeated keys are separate entries when their behavior changes. Multi-mode declarations keep their source modes together.
  • Leader stays literal: <leader> is the editor’s configured leader; this source file does not assign its value.
  • Hardware matters: modified arrows and mouse gestures depend on terminal support. Clipboard actions use Neovim’s system clipboard register.
  • No command execution: searches, disclosures, result inspection, and local preference work here. Selecting a mapping never sends keys or runs editor commands.
  • No outside resources: this standalone file uses inline styles and script. JetBrains Mono is used if installed, with local monospace fallbacks; no font download occurs.
  • Design judgment only: the recommendation is not measured usability evidence. Browser and assistive-technology verification remain separate from this prototype.

Option 03 / keyboard first / inline inspection

Keyboard-first command finder

Search for an action, then select a result to inspect its exact mapping. This is inline documentation, not an operating-system command palette.

While this search field has focus, Down Arrow focuses the first result. Within results, Up/Down or Home/End move focus; Enter or Space inspects. Escape returns to search. Tab always works. No global shortcuts are registered.

    Recommendation / browser-local decision

    Recommendation & choice

    Choose 01 for the primary cheatsheet. A reference must reveal the difference between Normal, Insert, Visual, and Select behavior without requiring another inspection step.

    Keep 02 in mind for task-led learning. Choose 03 if focused keyboard search matters more than comparing mappings simultaneously.

    Confidence: provisional design judgment. Open questions: do users search by intent or key, and how often do they compare modes? Observe those tasks before final implementation.
